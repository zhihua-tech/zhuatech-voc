# 架构与数据边界

上海如静知华信息科技有限公司 · https://www.zhuatech.cn/

## 请求链

H5 业务端 / 管理端 → REST API → 会话与角色验证 → 企业范围内事务锁 → 类型字段及业务关联验证 → Domain 业务规则 → 单据、下游记录、幂等结果和审计共同提交。

## 独立模块

| 模块 | 已实现功能 | 可执行操作 |
|---|---|---|
| 客户名册 | 用于受邀反馈和回访追踪；不含外部营销发送 | 新建、编辑、查询、详情、导出 |
| 满意度调查 | 发布调查、有效期、低分阈值与回访时限 | 审批发布、结束调查 |
| 客户反馈 | 同客户同问卷单次反馈，提交后锁定 | 确认录入、撤回并停止统计 |
| 回访工单 | 低分反馈自动转回访，分派、处理与复核 | 分派回访、登记回访结果、复核结案、重新处理 |
| 改进行动 | 关联回访根因、责任人与效果验证 | 落实改进、提交改善结果、效果验收 |

领域代码位于 `backend/src/main/java/cn/zhuatech/voc/Domain.java`。字段和状态动作位于 `catalog.json`，前端按其生成真实表单；计算、关联校验及状态约束只在后端判定。自动生成的流水模块禁止客户端手工创建。

## 持久化设计

- `business_record`：固定身份、企业、模块、状态、版本、创建者、业务编号与时间列；模块的类型化业务字段保存为 JSON 文本。
- `tenant_guard`：按企业行锁串行执行写事务，避免跨记录占用冲突和超扣库存。同企业写入因此不会无限并行，这是明确的吞吐取舍；不是大规模事件驱动库存平台。
- `idempotency_record`：按企业、操作者、请求键保存请求指纹和成功响应。重试同一请求返回相同结果，键被不同内容重用返回冲突。
- `audit_event`：保存前后快照、操作人和依据。用户接口不提供修改/删除；数据库管理权限不在此防篡改边界内。
- `attachment`：受鉴权的文件内容、大小和 SHA-256 摘要，单文件限制 2 MB。
- `app_user / auth_session`：BCrypt 密码、角色、启停与会话摘要；不存明文登录令牌。

动态业务关联由服务端在同一事务内验证，不是数据库外键模型。禁止通过 SQL 手工改写业务 JSON；新增模块必须同时更新字段约束、业务规则及测试。默认一套部署对应一家企业，服务端与测试保留租户隔离能力，无租户开户运营界面。

## 本项目关键事务

按有效反馈实时计算 NPS 与平均满意度。同客户同问卷避免重复录入，低分提交会自动生成带时限的回访工单；关联改进行动未验收时不能关单，撤回反馈不再进入统计。

一期为企业人员录入受邀客户反馈的 H5 工作台，不包含公开匿名问卷、短信/邮件营销、AI 文本分析或录音。客户撤回停止统计并隐藏当前反馈正文，既有审计保留，不等同于彻底删除全部个人数据。

## 确定性顺序

V2 迁移为业务记录与审计事件加入数据库自增顺序号。最新检测和审计排序不再依赖秒级时间或随机 UUID；同一秒连续录入的记录仍按实际插入顺序处理。
